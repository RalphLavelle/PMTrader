# Saved runs
Now that the runs are being saved to the database, we need to add a new route to the API to retrieve the runs from the database. The route should be /api/runs and should return the runs in the database. The runs should be returned in the same format as the runs returned by the /api/run route.

## Analyse the runs
Also, in order to help me understand what's happening in each run, I want a new skill to analyse the runs and return a summary of the run. The summary should include the following:

- The market ID
- The date and time of the run
- The participating agents
- The confidence scores
- The signals
- The risk assessment
- The recommendation
- The outcome
- The mode

These should be explained in plain English and should be easy to understand. The idea is this highly technical information has to be usable by someone who is not a market expert and has to make decisions based on the information.

The skill should be called `analyse_run` and should be added to the `skills` folder. It can be invoked by asking the agent to "analyse the latest run" and it should then return the summary. Alternatively, the market id, e.g. POLY-3013350, can be provided and the skill should return the summary for that market.

The skill should return a markdown report of the analysis, placed into the docs folder, and organised by folders corresponding to that market id.

Create this skill, then run it for the latest (and only) run in the database.

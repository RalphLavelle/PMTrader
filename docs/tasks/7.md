You are a senior Node architect with expertise in LangGraph, LangGraph Swarm, agentic AI systems, and quantitative trading systems.

You are extending an existing project called PMTrader.

Current architecture:

- Node/TypeScript backend
- LangGraph already exists for sequential market analysis
- The current graph performs:
    - fetch_market
    - technical_analysis
    - semantic_analysis
    - synthesize
- This graph should remain intact and continue working.

Your task is NOT to replace this graph.

Instead, introduce LangGraph Swarm as a higher-level orchestration layer.

## Objectives

Implement an initial multi-agent swarm that coordinates specialist trading agents.

Create these agents:

1. Market Analyst

- Fetches and prepares market data
- Calculates derived features
- Never recommends trades

2. Trend Agent

- Evaluates trend-following opportunities
- Returns structured confidence and reasoning

3. Mean Reversion Agent

- Evaluates reversal opportunities
- Returns structured confidence and reasoning

4. Semantic Agent

- Wraps the existing semantic analysis graph
- Uses the current LLM implementation

5. Risk Manager Agent

- Reviews all proposed trades
- Calculates position sizing
- Can veto trades

Use the official `langgraph_swarm` package.

Implement proper handoff tools between agents rather than a central supervisor.

Use shared swarm state.

Design all agents to return structured Pydantic models.

Create:

- `/agents`
- `/swarm`
- `/schemas`
- `/memory`

Keep all business logic separate from LangGraph glue code.

The architecture must make it easy to add future agents such as:

- Portfolio Manager
- Execution Agent
- Volatility Agent
- Learning Agent
- Regime Detection Agent

## Memory

Design interfaces for persistent memory, but keep the first implementation simple.

Each completed analysis should be stored with:

- timestamp
- market id
- participating agents
- individual confidence scores
- final recommendation
- trade outcome (optional for now)

The persistence layer should be abstract so SQLite, PostgreSQL, or vector databases can be substituted later.

## Coding style

- Node/TypeScript
- Full typing
- Small focused modules
- Comprehensive docstrings
- Unit-testable architecture
- No placeholder TODOs unless unavoidable

Produce production-quality code rather than an example.
